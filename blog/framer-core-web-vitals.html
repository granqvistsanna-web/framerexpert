Framer och Core Web Vitals 2026: Så får du topp-poäng i Google PageSpeed

Core Web Vitals är Googles tre mätvärden för användarupplevelse — och en direkt rankingfaktor. Framer-sajter klarar ofta dem automatiskt, men för att nå 100/100 i PageSpeed behöver du förstå vad du kan påverka. Här är den praktiska guiden.

Vad är Core Web Vitals och varför spelar det roll?

Core Web Vitals är tre mätvärden som Google använder för att bedöma sidans upplevelse. Sedan 2021 är de en officiell rankingfaktor, och 2026 väger de tyngre än någonsin för konkurrensutsatta nyckelord.

De tre mätvärdena är:

  • LCP — Largest Contentful Paint (laddningshastighet)
  • CLS — Cumulative Layout Shift (visuell stabilitet)
  • INP — Interaction to Next Paint (responsivitet)

LCP — så optimerar du laddningstiden

LCP mäter hur snabbt det största synliga elementet (oftast hero-bilden eller hero-rubriken) renderas. Bra < 2,5 s · Förbättra < 4,0 s · Dålig > 4,0 s.

I Framer påverkas LCP mest av:

  • hero-bildens storlek och format
  • custom fonts som laddas sent
  • blockerande tredjepartsskript i head

Åtgärder:

  • komprimera hero-bilden och ladda upp i rätt storlek
  • använd Framers inbyggda bildkomponent (WebP/AVIF)
  • preloada viktiga typsnitt via Custom Code
  • flytta icke-kritiska skript till end-of-body

CLS — visuell stabilitet

CLS mäter hur mycket layouten hoppar under laddningen. Bra < 0,1 · Förbättra < 0,25 · Dålig > 0,25.

Framer hanterar CLS väl eftersom plattformen reserverar plats för bilder och komponenter. Det du själv kan förstöra:

  • embeds utan fast höjd (YouTube, Twitter, Calendly)
  • custom fonts utan font-display: swap
  • reklam- eller cookie-banners som pushar innehåll

Lös det genom att alltid sätta fast höjd på embeds och reservera plats för banners.

INP — 2026:s viktigaste mätvärde

INP ersatte FID 2024 och mäter hur snabbt sidan svarar på alla användarinteraktioner, inte bara den första. Bra < 200 ms · Förbättra < 500 ms · Dålig > 500 ms.

Framer själv har snabb INP — men externa skript kan förstöra det. Vanliga bovar:

  • tunga analytics-skript
  • chat-widgets (Intercom, Drift)
  • A/B-testverktyg som blockerar main thread

Lösning: ladda dem defer/async, eller använd en tag manager som bara triggar efter user interaction.

Så mäter du Core Web Vitals

Tre verktyg du bör använda:

  • PageSpeed Insights — lab-data och fältdata per URL
  • Google Search Console — Core Web Vitals-rapporten visar status över tid
  • Chrome UX Report (CrUX) — verklig fältdata från användare

Mätning i lab (som Lighthouse) är snabbt, men det är fältdata som räknas för ranking.

Bilder och typsnitt — de största fällorna

Bilder och typsnitt står för 70–80 % av vikten på en typisk sida. Gör rätt här så är det mesta löst.

Bilder:

  • använd Framers bildkomponent (inte background-image i custom code)
  • ladda upp i max 2x display-storlek
  • sätt priority fetch på hero-bilder
  • aktivera lazy loading på bilder under fold

Typsnitt:

  • max 2 typsnittsfamiljer och 3–4 vikter totalt
  • hosta typsnitt själv om möjligt (undvik extra DNS-lookup)
  • preload critical font-file

Tredjepartsskript

Varje externt skript är en potentiell prestandarisk. Gör en audit:

  • behöver vi verkligen det här skriptet?
  • kan det laddas defer eller lazy?
  • kan funktionen ersättas med något lättare?

Chat-widgets och heatmap-verktyg är särskilt tunga. Överväg att bara ladda dem för inloggade användare eller efter 3 sekunder av inaktivitet.

Animationer utan att förstöra prestanda

Framers motion engine är kraftfull men kan göra sidan tung om du överanvänder den. Regler:

  • animera bara transform och opacity (GPU-accelererade)
  • undvik att animera width, height, top, left
  • begränsa antalet samtidiga animationer till max 5–10
  • använd prefers-reduced-motion för tillgänglighet och prestanda

Mobil vs desktop

Google använder mobile-first indexing — din mobilupplevelse är det som räknas. Mobila enheter har mindre RAM och långsammare nätverk, så testa alltid PageSpeed på mobilfliken först.

Vanliga mobilproblem:

  • onödigt stora bilder (behöver inte vara 2400 px breda på en 390 px-skärm)
  • complex hover-animation som fungerar sämre på touch
  • tunga bakgrundsvideor

Checklista: 10 steg till 100/100

  1. Komprimera hero-bilden till under 200 KB
  2. Preload critical font-file
  3. Flytta analytics till defer/async
  4. Sätt fast höjd på alla embeds
  5. Aktivera lazy loading på alla bilder under fold
  6. Minimera antalet typsnittsvikter
  7. Begränsa animationer till transform och opacity
  8. Ladda chat-widgets efter user interaction
  9. Verifiera i Search Console Core Web Vitals-rapport
  10. Mät på mobil först, desktop sedan

Slutsats

Framer ger dig bästa möjliga startpunkt för Core Web Vitals — men det är dina val kring bilder, typsnitt, animationer och externa skript som avgör slutresultatet. Gå igenom checklistan, mät med PageSpeed Insights och följ upp i Search Console. Topp-poäng är helt inom räckhåll.
